# Maintainer security control policy

Account ownership, MFA and an accountable responder must be established by actual humans; this document does not attest those facts. Maintain a real authorized-access inventory privately where exposing contacts would be inappropriate. Grant sensitive access manually only after checking role, scope and contributor identity. Require a second accountable maintainer for continuity before claiming that continuity exists. Never share or post App keys, recovery codes or session tokens.

Repository tokens default to contents read. Contributor tests have no administrative/publishing secrets, no untrusted pull_request_target, no installation hooks for submitted plugins, and no adapter execution. Publishing uses protected environments, explicit reviewed source and minimum OIDC rights. Corporate administrative tokens are issued outside PR jobs and restricted to the one repository and permission needed.

Dependency policy: hashed Python locks and native source pins are reviewed separately. Any advisory reported by the strict pinned-Python scan fails the dependency check; no severity is silently suppressed. Native-source findings require a dated assessment against the exact build and publication stop for known exploitable critical/high findings. Never label a scanner’s limited clean result proof of absence. A VEX statement requires a concrete reviewed reachability/mitigation assessment; none is fabricated for convenience.

Static-analysis policy: Ruff/mypy and Bandit run on proposed changes; Bandit medium/high findings fail the automated check. CodeQL runs independently and its alerts need accountable maintainer triage. Do not clear a finding or add blanket suppression to make CI green. A known unresolved exploitable critical/high issue blocks release regardless of whether a workflow exits successfully. Secret scan exceptions are exact reviewed public digests, not wildcard exclusions. External code inspection and independent review remain separate from scanner output.

Major functionality must include meaningful positive/negative tests, determinism, privacy/security regression and explicit coverage limits. All final required checks must match the accepted source. No reviewed release uses green evidence from a previous commit. Native build changes retain caller/compiler flags and preserve explicit source/notices; measure them in their actual build profile.

Public disclosure uses SECURITY.md and private GitHub reporting. Publish substantiated vulnerability information after coordinated handling, credit consenting reporters, and retain reproduction evidence with synthetic inputs. No production message becomes a public CI artifact. Normal Actions/security notifications need responsible humans subscribed and operating the process.
